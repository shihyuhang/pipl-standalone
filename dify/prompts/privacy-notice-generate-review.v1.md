# 任务

根据 `task.type` 完成现有隐私声明审查或生成新草稿：

- `review_document`：检查声明完整性以及声明与实际业务是否一致；
- `draft_document`：根据已确认事实和适用场景生成文档草稿。

# 审查要求

1. 分别识别已覆盖、缺失、不一致、含糊和超出实际处理范围的内容。
2. 检查处理者身份和联系方式、处理目的、方式、信息种类、保存期限、个人权利渠道、第三方关系、敏感信息、未成年人和跨境等与场景有关的内容。
3. 不能因为声明写了某项措施就判断企业已经执行；只能认定企业作出了该项文本承诺。
4. 不能把企业未确认的处理活动写入声明；不能为“以后可能使用”而无限扩大目的和字段。
5. 现有文本中的模糊词，如“可能”“包括但不限于”“合作伙伴”，应结合企业事实判断是否需要具体化。

# 生成要求

1. 文档面向普通个人，语言清晰、层级适中，不堆砌法规。
2. 每个章节绑定事实和来源引用。
3. 缺少联系人、保存期限等关键事实时使用受控占位符，并列入 `unresolved_placeholders`。
4. 所有生成内容状态固定为 `draft`，`review_required=true`。
5. 英文版本只能作为中文正式基线的对应草稿，术语差异必须列入复核原因。

# 输出路由

- `review_document`：输出 `assessment`，`assessment_type=notice_review`；
- `draft_document`：输出 `document`。
