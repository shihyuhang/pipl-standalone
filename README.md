# 个保轻舟单机版

当前版本：`v0.3.3`

面向小型个人信息处理者的一站式个人信息保护工作台。单机部署、数据默认保存在本地，当前版本已覆盖：

- 首页统一按当前单位事实实时计算适用路径，并以材料发布、自查归档和后续记录为证据展示合规建设进度；
- 单位或业务变化后在首页集中提示需要复核的已发布材料；

- 企业名称、单位类型、所属行业等基本信息建档与小型处理者路径判断；
- B2B、员工、官网等业务场景登记和简短事实确认；
- 完成业务情况后运行规则与 AI 辅助初步检查，失败时安全降级为本地基础检查；
- 保存每次检查的事实快照、分析版本、发现和历史结论；
- 业务事实修改后自动标记旧检查结果过时；
- 将检查发现一键转为可跟踪的合规待办；
- 通过四步向导建立对外规则与同意、内部制度、处理协议、业务台账和办理记录；
- 根据已确认企业和业务事实生成材料草稿，而非只生成通用模板；
- 合规材料版本管理，区分内容一致、需要确认、草稿待发布和已发布；
- 小型处理者采用“生成/编辑草稿—负责人直接发布”的简化流程，发布版本正文不可修改；
- 保存版本来源、事实快照、内容哈希、发布人、发布渠道和发布证据；
- 按消费者、业务联系人、员工、候选人和访客分别管理对外材料，员工与候选人严格分开；
- 同一人群的一份材料可覆盖多项业务，内部制度和台账可覆盖全部相关业务；
- 按“基础材料、条件触发、留痕材料”展示适用范围，补齐委托/共同处理协议、权利请求、同意撤回和安全事件等材料；
- 将合规审计自查表和个人信息保护影响评估纳入材料全景，并继续由专门模块完成判断、签署和归档；
- 在系统“AI 设置”中选择 DeepSeek、通义千问、Kimi 或其他 OpenAI 兼容服务，密钥加密保存在本机服务端；
- 材料向导支持“AI生成完整草稿”和“基础模板”，AI失败或未配置时自动安全降级；
- AI起草必须先经过提交预览；负责人可排除非必要字段，系统自动脱敏单位名称、联系人、联系方式及自由文本中的邮箱、电话、姓名和身份证件号码；
- AI仅收到负责人确认后的脱敏内容，返回后由本机服务恢复真实值再形成可编辑交付草稿；
- AI草稿保存模型、提示词版本和待确认事项，但不保存或展示API密钥；
- 业务或企业档案变化后自动定位关联材料和受影响章节；
- 任意版本逐行对比，支持说明无需修改、暂缓处理或创建修订草稿；
- 官方 24 项合规审计自查表数字化，按六组通俗问题逐项完成；
- 不符合项自动生成整改事项，“不适用”必须说明理由；
- 自查负责人确认、内容哈希冻结和官方顺序打印；
- 按具体业务触发个人信息保护影响评估，保留官方五类情形和三个判断维度；
- 影响评估发现风险或措施不足时自动生成处理事项；
- 影响评估负责人确认、内容哈希冻结和官方格式打印；
- 合规时间线和归档概览。

## 本地运行（不需要 Docker）

### Windows CMD 一键启动

在项目目录中运行：

```cmd
start-standalone.cmd
```

脚本会自动寻找当前工作区可用的 Node.js、创建 `.env.local` 并启动系统。

### PowerShell / 已安装 pnpm 的环境

```powershell
pnpm install
Copy-Item .env.example .env.local
pnpm dev
```

如果使用 Windows CMD，复制文件的命令是：

```cmd
copy .env.example .env.local
```

打开 `http://localhost:3000`。默认使用 Node 内置 SQLite，新安装的数据保存在 `data/pipl-standalone.db`。从旧版本升级时，如果目录中已有 `data/pipl-mvp.db`，系统会自动继续使用该数据库，不需要手工迁移。

## 接入 AI（不需要 Dify）

启动系统后，可以直接进入“AI 设置”，选择材料草稿使用的服务，填写接口地址、模型和API密钥，并测试连接。密钥使用本机凭据密钥加密后保存在 SQLite 中，页面不会回读明文。部署环境也可以设置 `PIPL_CREDENTIAL_SECRET` 作为固定的凭据加密主密钥。

如果希望通过部署环境统一配置，也可以继续使用下列环境变量。材料草稿选择“自动”时会复用已经配置的 DeepSeek、通义千问或 Kimi。

系统可以直接调用 DeepSeek、通义千问或 Kimi。只需选择一家并在 `.env.local` 中配置，例如 DeepSeek：

```env
AI_SCENARIO_TRIAGE_PROVIDER=deepseek
AI_SCENARIO_TRIAGE_FALLBACK_PROVIDER=local
DEEPSEEK_API_KEY=请在本地填写
DEEPSEEK_API_BASE_URL=https://api.deepseek.com
DEEPSEEK_MODEL=deepseek-v4-flash
```

通义千问使用 `DASHSCOPE_API_KEY`，Kimi 使用 `MOONSHOT_API_KEY`。也可以将 `AI_SCENARIO_TRIAGE_PROVIDER` 设为 `auto`，系统会选择已经配置的直连模型。密钥不得提交到代码仓库。

模型接口异常、输出被截断或结构不符合要求时，业务检查会退回基础规则检查，材料生成会退回基础模板。材料版本只记录实际使用的服务、模型、提示词版本和待确认事项，不记录API密钥。

## Dify 作为可选方案

已部署的 Dify 可以继续使用，但不再是必需组件。需要使用时，在 `.env.local` 中配置：

```env
DIFY_API_BASE_URL=https://dify.legalkit.xyz/v1
DIFY_ENABLE=true
DIFY_API_KEY_SCENARIO_TRIAGE=app-请在本地填写
AI_SCENARIO_TRIAGE_PROVIDER=dify
```

Dify 工作流应接受 `enterprise_context`、`scenario_context` 和 `confirmed_facts` 三个字符串输入，并通过 `result` 输出结构化 JSON。如需把 Dify 作为直连模型的备用服务，可设置 `AI_SCENARIO_TRIAGE_FALLBACK_PROVIDER=dify`。

```powershell
pnpm typecheck

```

本软件用于辅助小型个人信息处理者建立和维护合规工作记录，不构成合规认证或正式法律意见。AI 输出、官方自查结论、影响评估和正式材料发布均保留负责人确认点。

## v0.3 使用主链

1. 先在“我的业务”确认实际处理活动；
2. 在“合规自查”按六组通俗问题完成官方 24 项，自查线索仅用于辅助核对；
3. 暂不符合项目会进入“办理事项”，整改完成后回到自查更新结论；
4. 对系统提示或负责人确认触发的业务，在“影响评估”选择适用情形并完成三个判断；
5. 负责人确认后形成只读归档记录，并可按官方顺序打印；
6. 后续业务变化时建立新一期记录，不覆盖历史结论。

## v0.2 使用主链

1. 在“我的业务”完善并确认实际业务情况；
2. 运行“初步检查”，系统自动保存本次事实快照和检查结果；
3. 将需要处理的发现生成待办；
4. 在“合规材料”先选择面向人群，再选择材料类型；同一人群可一次关联多项业务，员工和候选人分别建立告知；
5. 系统生成完整草稿，负责人核对或修改后直接发布；
6. 业务情况变化后重新检查，并按需更新材料版本。
