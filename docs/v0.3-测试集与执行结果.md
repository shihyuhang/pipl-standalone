# V0.3 测试集与执行结果

执行日期：2026-08-11

## 一、测试目标

本测试集验证小型个人信息处理者从企业建档、业务事实确认、快速分析、任务联动到官方自查和影响评估的主要路径。测试数据均为合成数据，不包含真实企业或个人信息。

## 二、业务案例集

| 编号 | 案例 | 主要验证点 | 预期路径 |
|---|---|---|---|
| T01 | 少量联系人信息的外资B2B企业 | 外资身份不自动等于跨境，普通联系人不自动升级风险 | 适用小型处理者路径 |
| T02 | 人数已估算但口径尚未确认 | 未去重人数不能作为已确认事实 | 有条件继续并生成人数确认事项 |
| T03 | B2B系统服务商角色未知 | 不能仅按B2B属性判断处理角色 | 有条件继续并生成角色确认事项 |
| T04 | 员工管理涉及健康信息 | 敏感个人信息触发专项复核 | 需要人工复核 |
| T05 | 官网活动可能收到未成年人信息 | “尚不清楚”不能当作“不涉及” | 需要补充并进行风险复核 |
| T06 | 境外总部远程访问联系人信息 | 境外远程访问能够被识别 | 需要人工复核 |
| T07 | 99999人边界 | 低于10万人仍在小型处理者路径内 | 适用小型处理者路径 |
| T08 | 100000人边界 | 达到10万人时转出小型处理者路径 | 转专业人员评估 |
| T09 | 业务信息缺少保存期限 | 缺少必要事实时不能开始快速分析 | 保持业务待完善 |
| T10 | 外部接收方尚不清楚 | 不清楚服务商或接收方时提出补充问题 | 需要补充信息 |

案例源文件：`tests/fixtures/small-processor-scenarios.ts`。

## 三、数据库端到端流程

1. 建立企业档案和首个业务后，“添加首个业务场景”由系统自动完成；
2. 业务必要事实填写完整后，对应业务完善任务自动完成；
3. 建立首份对外告知材料后，对应材料任务自动完成；
4. 官方自查从“不合规”改为“合规”时，关联整改任务自动关闭；
5. 影响评估风险结论消除后，关联任务自动关闭；
6. 自动完成事项记录完成依据，而不是要求用户重复填写办理说明。

## 四、云端AI冒烟测试

使用与正式接口相同的最小化上下文，运行两条不含真实个人信息的合成案例：

- 普通外资B2B联系人案例：返回 `draft_ready`，没有L3阻断事项；场景人数、访问岗位、运维方、删除安排和个人权利渠道改为系统结构化采集后，AI只保留“明确云服务商角色”和“留存删除执行记录”2项非阻断建议；
- 员工健康信息案例：返回 `needs_review`，包含L3事项并要求人工复核；
- 两个案例均成功返回结构化结果；
- 用户可见结果未出现内部JSON字段名；
- 外资身份没有被直接推断为个人信息跨境。

可通过 `npm run test:ai` 单独重复该测试。未配置云端AI时会安全跳过，不影响本地测试。

## 六、尚未覆盖的测试

- 浏览器端完整点击流程和不同屏幕尺寸；
- 官方表单打印导出的逐页视觉比对；
- 云端AI超时、限流和长时间不可用；
- 多用户并发写入和多租户隔离；
- 大批量历史任务、文档版本和评估记录的性能；
- 专业人员对AI结论进行法律质量复核的金标评测。

这些内容适合在V0.4前逐步加入，不影响当前MVP的主要业务流程验证。

## 七、本轮测试后已完成的优化

1. 业务事实增加场景人数、可访问岗位、系统运维方、到期处理方式、个人权利渠道和自动化决策六项结构化字段；
2. 企业档案中的统一权利联系渠道自动带入业务，不再要求重复填写；
3. 旧业务按新的事实完整度实时重算，避免页面显示100%后又被AI要求补充；
4. 业务事实完成后自动关闭对应办理事项，缺少事实时保持待办；
5. 合规材料自动带入新增事实，审计自查中的自动化决策线索直接读取业务事实，不再根据“营销活动”猜测；
6. AI用户可见结果新增内部字段名过滤检查，调用失败时输出可定位原因并安全降级。
