# 合规材料与影响评估报告法律符合性审阅报告

**审阅对象**：个保轻舟 MVP v0.3.1 生成的 18 类合规材料模板（`src/lib/materials.ts`）及个人信息保护影响评估（PIPIA）报告
**审阅依据**：《个人信息保护法》（PIPL）、《网络数据安全管理条例》、《小型个人信息处理者个人信息保护简化措施规定》（网信办/公安部第 25 号令）及官方附件 1、附件 2
**审阅人视角**：执业律师对"能否作为合规工作底稿/对外法律文本"的基础要求
**审阅日期**：2026-08-18

---

## 一、总体结论

**18 类材料模板中，15 类达到"法律基础要求"，可作为合规工作底稿；3 类（敏感单独同意书、出境告知同意、委托/共同处理协议）为"框架达标、关键条款留白"，需人工补全或 AI 预填后方可使用。**

**PIPIA 报告（附件 2 形态）结构完整、三判断维度准确、签字声明规范，达到基础要求。**

系统的设计取向正确：**对外否定项明确（"不涉及"）、留白处显著标注"待补充"、不编造事实**——这对举证的完整性有利，比"看似完整实则虚构"的生成更负责任。

分级：**达标** = 要素齐全可直接用；**框架达标** = 结构对但需补关键内容；**待改进** = 存在要素缺失。

## 二、对外告知类（隐私规则及各人群告知）

**对应模板**：`privacy_notice` / `employee_notice` / `candidate_notice` / `b2b_contact_notice` / `visitor_notice`（共用同一生成器，仅 intro 不同）
**法条依据**：PIPL 第 17 条（告知事项）、第 13 条（处理基础）

### 审阅结论：**达标**

PIPL 第 17 条要求告知：①处理者名称/姓名和联系方式 ②处理目的、方式、信息种类 ③保存期限 ④个人权利行使方式和程序 ⑤其他法定事项。模板十章结构逐项覆盖：

| PIPL 第17条要素 | 模板覆盖 | 评价 |
|---|---|---|
| 处理者名称+联系方式 | 第九章"如何联系我们"（姓名/职务/渠道） | ✅ |
| 处理目的、方式、信息种类 | 第二章逐项业务列出（目的/信息/来源/系统） | ✅ |
| 保存期限 | 第二章"保存期限或删除条件"+第七章 | ✅ |
| 个人权利方式和程序 | 第八章"您的权利" | ✅ |
| 敏感信息（第30条必要性告知） | 第三章单独提示+指向单独同意 | ✅ |
| 未成年人（第31条） | 第四章专门说明 | ✅ |
| 对外提供（第23条） | 第五章 | ✅ |
| 出境（第39条） | 第六章 | ✅ |

**亮点**：对未涉及项明确写"不涉及"（如"当前已确认业务不涉及敏感个人信息"），而非模糊带过——这符合告知的准确性要求，且对处理者举证有利。

**小瑕疵（不阻断）**：第五章"处理方式和联系渠道：待逐家确认"——对外提供时，PIPL 第 23 条要求告知接收方名称、联系方式、处理目的、方式、信息种类。模板留了"待逐家确认"，正确做法是**发布前必须补全**，否则该条告知不完整。属合理留白但需发布校验。

## 三、敏感个人信息单独同意书

**对应模板**：`sensitive_consent`
**法条依据**：PIPL 第 29 条（单独同意）、第 30 条（必要性+影响告知）、第 28 条（敏感定义）

### 审阅结论：**框架达标（关键字段留白）**

| PIPL 要素 | 模板 | 评价 |
|---|---|---|
| 单独同意的明确意思表示 | "自愿、明确作出单独同意"+确认栏+日期 | ✅ 第29条满足 |
| 处理必要性告知（第30条） | "处理必要性：待结合实际业务补充" | ⚠️ **留白** |
| 对个人权益的影响（第30条） | "对个人权益的影响：待补充" | ⚠️ **留白** |
| 保护措施 | "访问权限、加密或去标识化…待确认" | ⚠️ **留白** |
| 撤回机制（第15条） | 撤回渠道+"不影响撤回前合法处理" | ✅ |

**核心问题**：PIPL 第 30 条是**强制性告知义务**——处理敏感信息前必须告知必要性和对个人权益的影响。当前这两项留白，意味着这份同意书**在补全前不具备法律效力**，个人在信息不充分时作出的"同意"可被挑战。

**这是 P1-2 缺陷的法律实质**。留白本身比编造好，但：① 界面必须强制提示"补全必要性和影响前不得发布使用"；② 优先对这类材料启用 AI 基于业务事实预填必要性/影响/措施草稿。

## 四、个人信息出境告知与单独同意

**对应模板**：`cross_border_notice_consent`
**法条依据**：PIPL 第 39 条（出境告知+单独同意）、第 38 条（出境条件）、《数据出境安全评估办法》

### 审阅结论：**框架达标（接收方信息留白）**

| PIPL 第39条要素 | 模板 | 评价 |
|---|---|---|
| 境外接收方名称 | "待逐项确认" | ⚠️ 留白 |
| 境外接收方联系方式 | 第二章列入"应填写完整" | ⚠️ 留白 |
| 处理目的、方式 | 已按业务列出 | ✅ |
| 个人信息种类 | 已列出 | ✅ |
| 个人向境外接收方行使权利的方式和程序 | 第二章提示需补充 | ⚠️ 留白 |
| 单独同意 | 确认栏+日期 | ✅ |
| 出境豁免提示 | "豁免不当然免除告知义务" | ✅ 准确 |

**法律要点**：PIPL 第 39 条要求告知"境外接收方的名称或者姓名、联系方式、处理目的、处理方式、个人信息的种类以及个人向境外接收方行使本法规定权利的方式和程序"。**境外接收方的具体名称和联系方式是必填项**，当前留白。

**亮点**：明确"出境程序豁免不当然免除告知义务；是否需要单独同意，应结合具体处理基础核对"——这一点很多合规工具都搞错（以为过了安全评估/标准合同就不用单独同意），系统表述准确。

## 八、权利请求处理指引 + 各类台账/记录

**对应模板**：`rights_guide` / `rights_request_register` / `processing_register` / `vendor_register` / `consent_record` / `incident_record` / `incident_plan` / `incident_notification`
**法条依据**：PIPL 第 50 条（权利响应机制）、第 55-56 条（PIPIA 记录）、第 57 条（事件处置通知）

### 审阅结论：**达标**

- **rights_guide**：受理→核验→定位→执行→答复五步闭环，含"只进行必要身份核验"（避免过度收集，符合最小必要）✅

## 九、个人信息保护影响评估（PIPIA）报告

**对应产出**：附件 2 形态的评估表（`OfficialPipiaPrint`）
**法条依据**：PIPL 第 55 条（评估情形）、第 56 条（评估内容）、官方附件 2

### 审阅结论：**达标**

| PIPL 第56条评估内容 | 报告覆盖 | 评价 |
|---|---|---|
| 处理目的、方式是否合法、正当、必要 | legality 判断列（官方表述） | ✅ |
| 对个人权益的影响及安全风险 | impact 判断列 | ✅ |
| 保护措施是否合法、有效并与风险相适应 | measureAdequacy 判断列 | ✅ |
| 评估情形（第55条五类） | P01-P05 全五类（敏感/自动化/委托提供公开/出境/其他重大影响） | ✅ |
| 备注（影响程度、风险、保护措施） | 备注列（官方括号说明） | ✅ |
| 签字与责任声明 | "本人已…如有不实，承担相应法律责任"+负责人签字+日期 | ✅ |

**评价**：三判断维度与 PIPL 第 56 条一一对应，五类情形与第 55 条完全对齐（P03 正确合并"委托处理、向其他处理者提供、公开"为第 55 条第(三)项原文表述）。附件 2 版式与官方一致。评估结论可追溯（签字归档+内容哈希），满足第 56 条"评估报告留存至少三年"的留痕要求（需配合系统存档机制）。

**小提示**：PIPL 第 56 条要求 PIPIA 报告"至少保存三年"，系统通过 signed 归档+哈希固化满足，但界面应提示"评估报告需留存三年，勿删除"。

## 十、审阅发现汇总（按法律风险排序）

| 级别 | 材料 | 问题 | 法律后果 | 建议 |
|---|---|---|---|---|
| 🟠 中 | 敏感单独同意书 | 必要性、权益影响、保护措施留白（PIPL 第30条强制告知） | 补全前同意可被认定无效 | 发布前强制校验+AI 预填必要性/影响 |
| 🟠 中 | 出境告知同意 | 境外接收方名称、联系方式留白（PIPL 第39条必填） | 出境告知不完整，单独同意效力存疑 | 发布前强制补全接收方信息 |
| 🟡 低 | 对外提供章节 | 接收方"待逐家确认"（PIPL 第23条） | 告知不完整 | 发布校验 |
| 🟡 低 | 委托/共同协议 | 期限、处理方式留白 | 合同签约时补，属正常 | 提示签约前补全 |
| 🟢 提示 | PIPIA 报告 | 三年留存要求界面未提示 | 留痕合规 | 界面加留存提示 |
| 🟢 提示 | 全部材料 | 标题用内部代号（如"XX·privacy_notice"） | 对外文本不规范 | 正式名与代号分离 |

## 十一、给史律师的使用建议

1. **可直接用的**（11 类）：各人群告知、未成年规则、内控、权利指引、各类台账记录、事件预案/记录/通知——要素齐全，发布前核对事实即可。
2. **必须补关键字段才能用的**（3 类）：敏感同意书（补必要性+影响+措施）、出境同意（补接收方名称+联系方式）、委托/共同协议（补主体+期限+方式）。**这些留白处是法定的强制性告知/约定事项，空着不具备法律效力**——但这是"诚实留白"而非"虚假完整"，方向正确。
3. **优先改进项**：敏感同意书和出境同意的 AI 预填（基于业务事实生成必要性/影响/接收方草稿），可把这两类从"框架"拉到"可用"。
