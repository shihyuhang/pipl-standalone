# 首期场景目录与评估矩阵 V1.0

> 状态：开发基线草案  
> 编制日期：2026-08-09  
> 适用对象：中国境内处理不满 10 万人个人信息的小型个人信息处理者  
> 规则基线：《小型个人信息处理者个人信息保护简化措施规定》及其官方附件

## 1. 设计目标

场景目录解决四个问题：

1. 用户应从哪个熟悉的业务入口开始，而不是面对法律术语；
2. 每类业务默认询问哪些事实、可以复用哪些已有事实；
3. 哪些情况只需形成简要留档，哪些需要整改、影响评估或专业复核；
4. 每个场景最终生成哪些隐私声明、官方表单、任务和证据。

首期不按“餐饮、零售、外资”等企业标签分别复制一套流程，而采用：

> 基础业务场景＋横切专项分支＋企业画像

例如，在华外资 B2B 企业通常组合使用“员工管理＋B2B 联系人管理＋全球系统/境外访问分支”，而不是进入一个笼统的“外资行业模板”。

## 2. 法规与时间边界

- 《个人信息保护法》要求处理活动遵循合法、正当、必要、诚信和最小范围原则，并规定告知、同意、敏感信息、第三方、跨境、个人权利、安全和影响评估等要求；
- 《网络数据安全管理条例》自 2025-01-01 施行，补充个人信息处理规则、安全措施和网络数据处理要求；
- 《个人信息保护合规审计管理办法》自 2025-05-01 施行；
- 《小型个人信息处理者个人信息保护简化措施规定》及其官方附件作为本产品首期统一规则基线；
- 官方附件是首期审计自查和 PIPIA 的固定输出结构。

主要官方来源：

- [《个人信息保护法》](https://www.cac.gov.cn/2021-08/20/c_1631050028355286.htm)
- [《网络数据安全管理条例》](https://www.cac.gov.cn/2024-09/30/c_1729384452307680.htm)
- [《个人信息保护合规审计管理办法》](https://www.cac.gov.cn/2025-02/14/c_1741233507681519.htm)
- [《小型个人信息处理者个人信息保护简化措施规定》](https://www.gzwxb.gov.cn/context/contextId/216547)
- [国家网信办答记者问](https://www.cac.gov.cn/2026-07/24/c_1786638889576451.htm)

## 3. 场景评估的五种出口

| 代码 | 用户展示 | 含义 | 后续动作 |
|---|---|---|---|
| `SIMPLE_RECORD` | 可以按基础步骤建立记录 | 暂未发现必须进入专项评估的事实 | 生成场景档案、声明/制度待办和简要留档 |
| `REMEDIATE_THEN_PROCEED` | 完善这些事项后开展 | 存在可明确整改的缺项 | 创建整改任务，关闭后重新检查 |
| `PIPIA_REQUIRED` | 需要完成影响评估 | 命中法定 PIPIA 情形 | 创建官方 PIPIA 实例和工作底稿 |
| `EXPERT_REVIEW` | 建议专业人员复核 | 事实不清、解释空间大或高风险 | 暂停正式放行，转专家工作台 |
| `OUT_OF_SMALL_SCOPE` | 已超出小型处理者路径 | 人数达到 10 万或业务明显超出产品服务边界 | 保留档案并转一般处理者方案 |

出口不是“合规认证”。即使是 `SIMPLE_RECORD`，也只表示当前场景可进入基础合规工作，不表示企业整体已经合规。

## 4. 首期基础业务场景

### 4.1 总览

| 场景代码 | 用户入口名称 | 典型企业 | 主要个人类别 | 首期自动化程度 |
|---|---|---|---|---|
| `SCN-B2B-CONTACT` | 管理客户和供应商联系人 | 外资/内资 B2B、贸易、咨询、技术服务 | 客户、供应商、合作伙伴联系人 | 高 |
| `SCN-RECRUITMENT` | 招聘和候选人简历 | 所有雇主 | 候选人 | 高；敏感/背景调查转专项 |
| `SCN-EMPLOYEE-HR` | 员工入职和日常人事管理 | 所有雇主、外资企业 | 员工、离职员工 | 高；全球 HR 触发跨境分支 |
| `SCN-WEB-CONTACT` | 官网咨询、报名或售后联系 | B2B/B2C 小企业 | 咨询人、客户联系人、消费者 | 高 |
| `SCN-DIRECT-MARKETING` | 邮件、短信或电话营销 | B2B/B2C 小企业 | 联系人、会员、潜在客户 | 中；公开来源/画像另分支 |
| `SCN-MEMBER-SERVICE` | 普通会员和客户服务 | 零售、服务、简单电商 | 会员、消费者 | 中高 |
| `SCN-VISITOR-ACCESS` | 访客登记和普通门禁 | 办公场所、工厂、门店 | 访客 | 中 |
| `SCN-CCTV` | 普通视频监控 | 门店、办公室、仓库 | 访客、员工、消费者 | 中；人脸识别转专家 |

第三方 SaaS、全球系统、敏感信息、未成年人、自动化决策、公开信息、对外提供和境外访问不是独立“行业”，而是任何基础场景均可触发的横切分支。

## 5. 场景一：B2B 客户和供应商联系人

### 5.1 适用范围

用于项目交付、采购、售后、客户关系和正常商务联系而处理自然人联系人信息。纯企业名称、企业地址、统一社会信用代码、企业总机等不直接建立个人信息活动；姓名、职位、工作邮箱、手机号和沟通记录等进入本场景。

### 5.2 默认事实

| 维度 | 默认候选，不得自动确认 |
|---|---|
| 个人类别 | 客户联系人、供应商联系人、合作伙伴联系人 |
| 常见字段 | 姓名、企业、职位、工作邮箱、工作电话、手机号、沟通记录 |
| 常见目的 | 项目交付、采购、售后、客户关系管理 |
| 常见系统 | CRM、企业邮箱、工单、通讯录、文件存储 |
| 常见来源 | 本人、其所在企业、名片、企业官网、公开渠道 |

### 5.3 必问和分支

- 是纯企业资料还是包含自然人联系人；
- 联系方式来自本人、所在企业还是公开来源；
- 正常项目联系和产品营销是否分开；
- 联系人离职、项目结束、明确拒绝后怎样更新和删除；
- 是否进入集团 CRM 或被关联公司访问；
- 是否提供给渠道商或其他合作方；
- 是否收集身份证、银行账户、私人联系方式等超出普通商务联系所需的信息。

### 5.4 评估矩阵

| 事实组合 | 出口 | 触发内容 |
|---|---|---|
| 只有纯企业资料，确认不含可识别自然人信息 | `SIMPLE_RECORD` 或结束场景 | 保存判断依据，不创建个人信息处理活动 |
| 普通联系人信息，仅用于项目/采购/售后，范围清楚 | `SIMPLE_RECORD` | 生成 B2B 联系人告知、保存和权利任务 |
| 同一名单同时用于营销，但未提供拒绝方式 | `REMEDIATE_THEN_PROCEED` | 拆分目的、补告知和拒绝机制 |
| 来源为公开渠道且用途超出公开目的或个人已拒绝 | `REMEDIATE_THEN_PROCEED`/`EXPERT_REVIEW` | 官方审计 A11 |
| 提供给其他处理者、公开或委托处理 | `PIPIA_REQUIRED` | P03，审计 A04/A05/A07/A09 |
| 集团 CRM 在境外存储或境外人员可访问 | `PIPIA_REQUIRED` | P04，跨境事实和告知/单独同意分支 |
| 无法确认谁决定目的和方式 | `EXPERT_REVIEW` | 共同、委托、提供关系分类 |

### 5.5 输出

- B2B 联系人场景档案；
- B2B 联系人隐私告知/处理规则草稿；
- CRM、邮箱、合作方和保存期限清单；
- 必要时 P03/P04 影响评估；
- 相关审计项工作底稿：A01—A07、A11、A14—A19、A22。

### 5.6 Dify 介入

可用于从隐私声明、CRM 说明和合同中提取候选字段、目的和接收方，以及比对告知与实际业务。纯企业资料判断、是否达到人数门槛、跨境事实确认和正式第三方关系分类不由 Dify 单独决定。

## 6. 场景二：招聘和候选人简历

### 6.1 默认事实

个人类别为招聘候选人；常见信息包括姓名、联系方式、教育经历、工作经历、期望职位和面试评价。身份证件、健康、背景调查、犯罪记录等不得作为普通默认字段。

### 6.2 评估矩阵

| 事实组合 | 出口 | 触发内容 |
|---|---|---|
| 普通简历，仅用于本次招聘，期限清楚 | `SIMPLE_RECORD` | 招聘告知、访问权限、到期删除 |
| 招聘失败后进入人才库但未单独说明期限和用途 | `REMEDIATE_THEN_PROCEED` | 明确二次目的、期限和选择机制 |
| 招聘平台或猎头按企业指示处理 | `PIPIA_REQUIRED` | P03 委托处理、合同和监督 |
| 处理身份证、健康、背景调查等敏感信息 | `PIPIA_REQUIRED` | P01、A12；必要性、告知、单独同意 |
| 境外总部参与筛选或全球 ATS 可访问 | `PIPIA_REQUIRED` | P04、跨境招聘/HR 分支 |
| 使用 AI 自动筛选并可能实质影响录用 | `PIPIA_REQUIRED`＋可能 `EXPERT_REVIEW` | P02、透明度、解释和人工复核 |
| 无法说明背景调查来源或必要性 | `EXPERT_REVIEW` | 高风险事实不足 |

### 6.3 输出

- 招聘候选人告知；
- 人才库选择/告知材料；
- 招聘系统与供应商清单；
- 保存和删除任务；
- 必要时 P01/P02/P03/P04。

## 7. 场景三：员工入职和人事管理

### 7.1 默认事实

个人类别包括在职和离职员工；目的按劳动合同、人力资源管理、薪酬福利、考勤、培训、安全和法定义务拆分。员工管理并非天然以同意为唯一依据，系统应先收集劳动规章制度、集体合同和法定义务等事实，再由规则判断适用路径。

### 7.2 评估矩阵

| 事实组合 | 出口 | 触发内容 |
|---|---|---|
| 普通员工档案，目的、权限、期限清楚 | `SIMPLE_RECORD` | 员工告知、权限和离职删除/限制处理 |
| 员工数据用于与人事无直接关系的营销或画像 | `REMEDIATE_THEN_PROCEED`/`EXPERT_REVIEW` | 目的拆分、必要性和告知 |
| 薪资账户、健康、体检、身份证件等敏感信息 | `PIPIA_REQUIRED` | P01、A12 |
| 使用考勤/门禁供应商或外包薪酬 | `PIPIA_REQUIRED` | P03 委托处理 |
| 全球 HR、集团邮箱或境外 HR 可以查看 | `PIPIA_REQUIRED` | P04；记录是否符合跨境 HR 等简化条件的事实 |
| 人脸或指纹作为强制考勤且无替代方式 | `EXPERT_REVIEW` | 生物识别、必要性和替代方案 |
| 离职账号未关闭、权限未回收 | `REMEDIATE_THEN_PROCEED` | A18/A19 整改 |

### 7.3 外资企业特别说明

- 外资身份本身不触发 P04；
- 需要逐个确认全球 HR、邮箱、CRM、文件存储的存储地和境外访问；
- 第 25 号令第十条列明跨境人力资源管理等特定条件下的程序简化，但告知、单独同意等义务仍需按规定履行；
- 重要数据、关基身份、敏感信息数量或事实不清时不得自动判断适用简化。

## 8. 场景四：官网咨询、报名或售后联系

### 8.1 评估矩阵

| 事实组合 | 出口 | 触发内容 |
|---|---|---|
| 姓名、工作联系方式和咨询内容，字段最少 | `SIMPLE_RECORD` | 网站告知、保存期限、权利入口 |
| 强制收集与咨询无关的身份证、生日或私人地址 | `REMEDIATE_THEN_PROCEED` | 删除非必要字段 |
| 表单数据同步到 CRM、客服 SaaS | `PIPIA_REQUIRED` | P03 委托处理 |
| 同步境外系统或由境外团队处理 | `PIPIA_REQUIRED` | P04 |
| 默认勾选营销或提交即视为全部营销同意 | `REMEDIATE_THEN_PROCEED` | 分开营销目的和选择机制 |
| 面向未成年人报名 | `EXPERT_REVIEW` | 未成年人专门规则和监护人机制 |

### 8.2 输出

网站隐私声明/表单告知、字段最小化任务、CRM/客服供应商记录、保存期限、权利入口和必要的 P03/P04。

## 9. 场景五：邮件、短信或电话营销

### 9.1 必问

- 名单来源；
- 营销目的是否在原告知范围内；
- 是否基于个人特征进行画像或自动选择；
- 是否提供便捷拒绝/退订；
- 拒绝后是否进入抑制名单并停止发送；
- 是否由第三方营销平台发送；
- 是否向渠道商提供名单。

### 9.2 评估矩阵

| 事实组合 | 出口 | 触发内容 |
|---|---|---|
| 已清楚告知、名单来源明确、提供退订 | `SIMPLE_RECORD` | 营销活动留档和拒绝机制 |
| 公开邮箱/手机号用于与公开目的无关营销 | `REMEDIATE_THEN_PROCEED`/`EXPERT_REVIEW` | A11 |
| 个人已拒绝但仍发送 | `REMEDIATE_THEN_PROCEED` | 立即停止、更新抑制名单 |
| 通过画像或自动化决策选择人群 | `PIPIA_REQUIRED` | P02、A08 |
| 委托短信/邮件服务商 | `PIPIA_REQUIRED` | P03、A05 |
| 向渠道商提供名单 | `PIPIA_REQUIRED` | P03、A07、单独同意和告知 |
| 无法说明名单来源 | `EXPERT_REVIEW` | 暂停正式放行 |

## 10. 场景六：普通会员和客户服务

### 10.1 适用范围

适用于姓名、手机号、账号、订单、积分和普通售后记录，不覆盖人脸会员、健康档案、金融服务或面向未成年人核心业务。

### 10.2 评估矩阵

| 事实组合 | 出口 | 触发内容 |
|---|---|---|
| 普通会员字段、基础服务必需、无提供/公开 | `SIMPLE_RECORD` | 处理规则、注销和删除、权利入口 |
| 强制生日、性别、家庭情况等非必要字段 | `REMEDIATE_THEN_PROCEED` | 改为选填或删除 |
| 会员画像和个性化营销 | `PIPIA_REQUIRED` 或整改 | 是否构成自动化决策，P02 |
| 使用会员 SaaS、短信、云存储 | `PIPIA_REQUIRED` | P03 |
| 收集精确位置、健康、人脸等 | `PIPIA_REQUIRED`＋可能 `EXPERT_REVIEW` | P01 |
| 涉及未满十四周岁 | `EXPERT_REVIEW` | 专门规则和监护人同意 |

## 11. 场景七：访客登记和普通门禁

### 11.1 评估矩阵

| 事实组合 | 出口 | 触发内容 |
|---|---|---|
| 姓名、被访人、到访时间，短期保存 | `SIMPLE_RECORD` | 线下告知、期限、权限 |
| 强制登记身份证完整复印件但无充分必要性 | `REMEDIATE_THEN_PROCEED`/`EXPERT_REVIEW` | 敏感信息、字段最小化 |

## 12. 场景八：普通视频监控

### 12.1 范围

首期仅支持普通视频图像采集。人脸识别、行为分析、跨门店追踪、对外公开视频或用于绩效管理等进入专业复核。

### 12.2 评估矩阵

| 事实组合 | 出口 | 触发内容 |
|---|---|---|
| 为维护公共安全所必需，位置合理，有显著标识 | `SIMPLE_RECORD` | 设备清单、标识照片、权限和期限 |
| 用于营销、客流画像或员工绩效 | `EXPERT_REVIEW` | 目的变化、自动化/重大影响 |

| 境外存储或访问 | `PIPIA_REQUIRED`＋`EXPERT_REVIEW` | P04 |
| 人脸识别或身份比对 | `EXPERT_REVIEW` | P01、A10、替代机制 |

## 13. 横切专项分支

### 13.1 敏感个人信息 `BR-SENSITIVE`

触发事实：任一数据字段为敏感或不清楚。固定动作：确认类别、特定目的、充分必要性、替代方式、告知必要性和影响、单独/书面同意、访问控制、P01。生物识别、医疗健康或事实矛盾时转专家。

### 13.2 未成年人 `BR-MINOR`

触发事实：可能涉及不满十四周岁。固定动作：专门处理规则、监护人告知和同意、必要性、非必要信息不得强制、专项保护。首期默认专业复核。

### 13.3 第三方关系 `BR-THIRD-PARTY`

先询问谁决定目的和方式、能否自用、合同、再委托和终止删除，再由规则/人工分类为共同处理、委托、向其他处理者提供或独立处理。命中 P03；不得让用户仅凭法律术语自行选择。

### 13.4 境外存储或访问 `BR-CROSS-BORDER`

触发事实：境外存储、传输、远程访问、集团共享或境外运维得到确认。固定动作：接收方、国家、目的、字段、个人类别、一般/敏感人数、频率、措施、程序事实、告知和单独同意、P04。外资身份不单独触发。

### 13.5 自动化决策 `BR-AUTOMATED`

触发事实：画像、评分、推荐、排序、自动筛选或重大影响决定。固定动作：输入、输出、透明度、公平性、解释、拒绝、非个性化选项、人工复核、P02。

### 13.6 公开和已公开信息 `BR-PUBLIC`

区分“企业公开个人信息”和“处理来源于公开渠道的信息”；分别检查单独同意/PIPIA，或公开目的、合理范围、个人拒绝和重大影响。

## 14. PIPIA 触发矩阵

| 官方情形 | 后端确定性触发 | 需要 AI 辅助的部分 | 默认人工门槛 |
|---|---|---|---|
| P01 敏感个人信息 | `DATA.IS_SENSITIVE = yes` | 必要性、影响、风险和措施草稿 | 生物识别、医疗、事实矛盾 |
| P02 自动化决策 | `ACT.AUTOMATED_DECISION = yes` | 是否重大影响、公平透明分析 | 录用、定价、资格等重大决定 |
| P03 委托/提供/公开 | 关系被确认或公开为真 | 第三方关系候选分类、合同差距 | 关系不清或对方可自用 |
| P04 境外提供 | 已确认境外存储/传输/访问/共享 | 风险和措施草稿 | 重要数据、关基、敏感数量不清 |
| P05 其他重大影响 | 硬规则命中或专家指定 | 语义判断和场景风险 | 默认需人工确认触发 |

## 17. 场景状态

```text
draft
→ interviewing
→ facts_to_confirm
→ triaged
→ remediating / pipia_in_progress / expert_review
→ ready
→ active
→ needs_review
→ ended
```

`active` 只表示该场景已完成当前要求的内部流程，不表示企业整体合规。业务字段、系统、接收方、目的、保存期限或法规变化时转为 `needs_review`。

## 18. 首期金标案例

至少建立以下 20 个用例：

1. 纯企业客户资料，无自然人信息；
2. 普通 B2B 联系人，本地 CRM；
3. B2B 联系人用于营销且可退订；
4. 公开邮箱被用于无关营销；
5. 外资 B2B，但所有数据境内且境外不可访问；
6. 外资 B2B，全球 CRM 在新加坡；
7. 普通招聘，本次职位结束即删除；
8. 招聘简历进入人才库但未说明；
9. 候选人健康和背景调查；
10. 普通员工管理；
11. 全球 HR 访问中国员工信息；
12. 人脸考勤且无替代方式；
13. 官网咨询表单字段最小；
14. 官网咨询强制身份证；
15. 第三方短信营销；
16. 普通会员服务；
17. 未成年人会员；
18. 普通访客登记；
19. 普通 CCTV 且有标识；
20. CCTV 用于人脸识别或员工绩效。

每个用例校验：问题路径、事实快照、场景出口、PIPIA 触发、官方审计映射、专业复核门槛、输出材料和不得出现的错误结论。

## 19. 验收门槛

- 场景选择不要求用户理解法律术语；
- B2B 纯企业资料与自然人联系人能够区分；
- 外资身份不会自动触发 P04；
- 已确认境外远程访问一定进入 P04；
- 命中敏感、自动化、第三方或境外情形时不会漏建 PIPIA；
- 处理不满十四周岁信息默认转专门分支；
- 任何达到 10 万人的企业退出正式小型处理者路径；
- 场景的每个正式结论能追溯事实、规则、法规和证据；
- 所有场景统一使用经批准的法规和规则包版本，不设置施行日期双轨分支；
- 修改场景事实能正确标记受影响的隐私声明和历史评估需复核。
